# Антибот-защита форм регистрации — методичка для разработчика

Документ для передачи разработчику другого сайта. Описывает, как блокировать
автоматические (бот) регистрации. Стек-независимый: принципы + псевдокод + готовый
референс на Django (как сделано на splithome.ru).

---

## 0. Что за проблема

Форма регистрации без защиты собирает бот-аккаунты. Реальный кейс (splithome.ru,
июнь 2026): за ~4 дня **22 из 24 аккаунтов оказались ботами**. Характерный почерк
бот-регистраций (по нему же их потом отличают от живых):

- **Иностранные телефоны** (`+1-...`), хотя аудитория сайта — РФ;
- **мусор в текстовых полях** — случайные строки вроде `vzxyppuwyu`, `dqkvdpetqi`
  (бот заполняет каждое поле «чем-нибудь»);
- **одноразовые/иностранные email** (gmail/hotmail/aol/outlook, незнакомые домены);
- регистрация **строго через POST формы**, очень быстро, пачками (раз в N минут);
- профиль заполнен «механически»: имя/компания пустые, согласие на ПД проставлено.

Ущерб: засорение базы, ложные «лиды», а если регистрация что-то даёт автоматически
(скидку, доступ, бонус) — боты это получают.

---

## 1. Главный принцип

**Защита в глубину (defense in depth):** один приём не панацея, ставим несколько
дешёвых слоёв. Бот обходит один — спотыкается о следующий.

**Железное правило: вся валидация — на сервере.** Любые проверки в браузере
(JS, `required`, `pattern`) — косметика для удобства, бот шлёт POST напрямую,
минуя их. Сервер обязан перепроверять всё сам.

Приоритет внедрения — по соотношению «эффект / трудозатраты»:

| № | Слой | Эффект | Труд | Ставить |
|---|------|--------|------|---------|
| 1 | Серверная валидация бизнес-правил (телефон, email и т.п.) | Высокий | Низкий | **Всегда** |
| 2 | Honeypot (поле-ловушка) | Высокий | Низкий | **Всегда** |
| 3 | Time-trap (минимальное время заполнения) | Средний | Низкий | Рекомендуется |
| 4 | Rate-limit по IP | Средний | Средний | Рекомендуется |
| 5 | Подтверждение email/телефона (OTP / double opt-in) | Очень высокий | Средний | Если поток не падает |
| 6 | CAPTCHA (Turnstile/reCAPTCHA/hCaptcha) | Высокий | Средний | Крайняя мера |
| 7 | Не выдавать ценность до модерации | Снижает мотив | Низкий | По бизнесу |
| 8 | WAF / Bot Fight (Cloudflare) | Высокий | Низкий | Если есть Cloudflare |

Слои 1–2 в типичной волне отсекают почти всё. Остальное — по нарастанию.

## 2. Слои защиты — подробно

### Слой 1. Серверная валидация бизнес-правил

Отклоняй данные, которые не имеют смысла для твоей аудитории. В кейсе splithome
все боты слали `+1-...` → проверка «только РФ-номер» убрала всю волну разом.

**Идея:** нормализуй и проверь телефон/email/город по реальным правилам бизнеса.

Псевдокод (любой стек):
```
digits = удалить_всё_кроме_цифр(phone)
если длина(digits)==11 и digits[0]=='8': digits = '7' + digits[1:]   # 8XXX → 7XXX
если длина(digits)!=11 или digits[0]!='7':
    ОТКЛОНИТЬ("Введите российский номер в формате +7 XXX XXX-XX-XX")
phone = '+' + digits   # сохраняем в едином формате
```
Аналогично можно: блок-лист одноразовых почтовых доменов, требование заполненного
ФИО, проверка ИНН для юрлиц и т.д.

### Слой 2. Honeypot («горшочек с мёдом»)

Скрытое поле, которого **живой человек не видит** (спрятано стилем), а **бот-
автозаполнитель заполняет**. Если поле пришло непустым → это бот.

Ключевые правила:
- Поле должно **присутствовать в HTML** (иначе боту нечего заполнять), но быть
  **скрыто CSS**, а не `type="hidden"` — многие боты пропускают hidden-поля.
- Прятать через `position:absolute; left:-9999px` (или класс с `display:none`).
  Добавить `tabindex="-1"`, `autocomplete="off"`, `aria-hidden="true"` — чтобы
  живой пользователь (в т.ч. со скринридером и автозаполнением браузера) не задел.
- Имя поля — «приманка»: `website`, `url`, `nickname`, `company2`.
- **Ошибку человеку не показывай** — поле скрыто, просто молча отклоняй.

HTML (любой стек):
```html
<div aria-hidden="true" style="position:absolute;left:-9999px;top:-9999px;height:0;width:0;overflow:hidden">
  <label>Сайт</label>
  <input type="text" name="website" value="" tabindex="-1" autocomplete="off">
</div>
```
Сервер:
```
если trim(request.website) != "":
    ОТКЛОНИТЬ()   # молча, без видимой ошибки
```

### Слой 3. Time-trap (минимальное время заполнения)

Человек не заполнит форму за 1 секунду, бот — мгновенно.

```
# при отдаче формы кладём подписанную метку времени в скрытое поле ts
# при приёме:
прошло = сейчас() - ts
если прошло < 2 секунд:   ОТКЛОНИТЬ()    # слишком быстро = бот
если прошло > 2 часов:    ОТКЛОНИТЬ/обновить токен  # протухло
```
Метку времени **подписывай** (HMAC/секрет сервера или CSRF-механизм), иначе бот
просто подставит «правильное» значение.

### Слой 4. Rate-limit по IP

Не больше N регистраций с одного IP за период.

```
ключ = "reg:" + IP_клиента
счётчик = inc(ключ); expire(ключ, 1 час)
если счётчик > 5:  ОТКЛОНИТЬ(429, "Слишком много попыток, попробуйте позже")
```
Хранилище: Redis/Memcached (есть почти везде). Учитывай реальный IP за прокси
(`X-Forwarded-For`). Лимит подбирай так, чтобы не бить по NAT/общим сетям.

### Слой 5. Подтверждение email или телефона (самый сильный приём)

Аккаунт неактивен, пока не подтверждён код:
- **Email double opt-in:** на почту — ссылка/код; без перехода аккаунт не активен.
- **Телефон OTP:** SMS/звонок с кодом.

Бот с одноразовой почтой код не подтвердит → аккаунт так и останется «висеть» и не
получит никакой ценности. Минус — лишний шаг для живого пользователя, поэтому
включают, если предыдущие слои не справляются.

### Слой 6. CAPTCHA — крайняя мера

Если поток ботов сохраняется, добавь невидимую/лёгкую капчу:
- **Cloudflare Turnstile** (бесплатно, без раздражающих картинок) — предпочтительно;
- reCAPTCHA v3 (скоринг) или hCaptcha.

Всегда проверяй токен капчи **на сервере** (запрос к API провайдера). Капчу ставят
последней, потому что она добавляет трение реальным людям.

### Слой 7. Не выдавать ценность до модерации

В кейсе splithome бот сразу получал `is_approved=true` и скидку 15%. Если
регистрация что-то даёт автоматически — рассмотри выдачу **только после** ручной
модерации или подтверждения. (Это бизнес-решение: повышает трение, но убивает
мотив спама.)

### Слой 8. Инфраструктура (WAF / Cloudflare)

Если сайт за Cloudflare — включи **Bot Fight Mode** и базовые WAF-правила (или
rate-limit на уровне CDN на путь `/register`). Ловит ботов до прихода на сервер.

---

## 3. Что НЕ сломать (чтобы не пострадали живые)

- Honeypot прячь корректно (offscreen + `aria-hidden` + `tabindex=-1`), иначе
  скринридеры/автозаполнение браузера заполнят его у реального человека → ложный бан.
- Понятные тексты ошибок на видимых полях (телефон, email).
- Не вешай агрессивную капчу сразу — только если слои 1–4 не справились.
- Rate-limit не делай слишком жёстким (офис/мобильный оператор = общий IP).
- После внедрения **проверь живую регистрацию сам** (см. раздел 5).

## 4. Референс-реализация (Django, splithome.ru)

Что реально стоит на проде сейчас — два слоя (1 и 2). Можно скопировать как образец.

**Форма** (`apps/accounts/forms.py`) — общий базовый класс для всех форм регистрации:
```python
import re
from django import forms
from django.core.exceptions import ValidationError

class _BaseRegForm(UserCreationForm):
    # Honeypot: скрыто стилем в шаблоне; человек не видит, бот заполняет.
    website = forms.CharField(
        required=False, label='Сайт',
        widget=forms.TextInput(attrs={'autocomplete': 'off', 'tabindex': '-1'}),
    )

    def clean_website(self):
        if (self.cleaned_data.get('website') or '').strip():
            raise ValidationError('Регистрация отклонена.')   # бот
        return ''

    def clean_phone(self):
        raw = (self.cleaned_data.get('phone') or '').strip()
        digits = re.sub(r'\D', '', raw)
        if len(digits) == 11 and digits[0] == '8':
            digits = '7' + digits[1:]
        if len(digits) != 11 or digits[0] != '7':
            raise ValidationError('Введите российский номер в формате +7 XXX XXX-XX-XX.')
        return '+' + digits
```

**Шаблон** (`templates/accounts/register.html`) — honeypot скрыт, в обеих формах:
```html
<div aria-hidden="true" style="position:absolute;left:-9999px;top:-9999px;height:0;width:0;overflow:hidden">
  <label>Сайт</label>
  <input type="text" name="website" value="" tabindex="-1" autocomplete="off">
</div>
```
(В форме, где поля рендерятся циклом, honeypot из цикла исключается и вставляется
этим блоком вручную, чтобы он был скрыт.)

**Тесты** (`apps/accounts/tests/test_registration.py`): honeypot-заполнен → невалидно;
`+1`-телефон → невалидно; `8XXX` → нормализуется в `+7XXX`.

## 5. Чек-лист внедрения (для разработчика второго сайта)

1. [ ] **Вся валидация — на сервере** (клиентскую не считаем защитой).
2. [ ] Добавить **серверные бизнес-проверки** (телефон РФ-формат, и т.п.) — Слой 1.
3. [ ] Добавить **honeypot**-поле (скрыто CSS) + серверная проверка «непусто → бот» — Слой 2.
4. [ ] (Рекомендуется) **Time-trap**: подписанная метка времени, отказ если <2 сек.
5. [ ] (Рекомендуется) **Rate-limit по IP** на эндпоинт регистрации.
6. [ ] Если поток остаётся — **подтверждение email/телефона** и/или **Turnstile/капча**.
7. [ ] Проверить, **не выдаётся ли ценность автоматически** до модерации.
8. [ ] Если есть **Cloudflare** — включить Bot Fight Mode / WAF на `/register`.
9. [ ] **Логировать** отклонённые попытки (IP, причина) — чтобы видеть, что защита работает.
10. [ ] Не сломать живым: honeypot спрятан корректно, тексты ошибок понятны.

## 6. Как проверить, что защита работает

Имитируй бота и убедись, что аккаунт **не создаётся**:

```bash
# 1) GET формы → получить cookie + CSRF-токен (если есть)
# 2) POST как бот: иностранный телефон ИЛИ заполненный honeypot
curl -s -b cj.txt -H "Referer: https://САЙТ/register/" \
  -d "csrfmiddlewaretoken=$TOKEN" \
  -d "email=bottest@example.com" -d "phone=+1-826-851-7512" \
  -d "website=http://spam" \
  -d "password1=Test12345!" -d "password2=Test12345!" \
  https://САЙТ/register/
# Ожидаем: пользователь НЕ появился в базе (главный критерий).
```
И отдельно — что **живая** регистрация с корректным РФ-номером и пустым honeypot
**проходит**. Зафиксируй оба случая автотестами.

---

## TL;DR

1. Проверяй всё **на сервере**.
2. Поставь **honeypot** + **валидацию телефона/данных по бизнес-правилам** — это
   90% эффекта за час работы.
3. Если мало — **rate-limit**, **подтверждение email/телефона**, затем **капча**.
4. Не давай ботам ценность автоматически и **проверь, что живые проходят**.
