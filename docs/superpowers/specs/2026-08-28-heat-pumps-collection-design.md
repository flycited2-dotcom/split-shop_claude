# Подборка «Тепловые насосы» — дизайн

**Дата:** 2026-08-28
**Статус:** согласован владельцем, готов к планированию реализации
**Этап:** 1 из 5 (расширение товарной матрицы SplitHome)

---

## 1. Проблема

Ссылка «тепловые насосы» из группы ВКонтакте приводит покупателя не на splithome.ru,
а на сторонний сайт — вплоть до сушильных машин с тепловым насосом. Причина: на сайте
нет ни вкладки, ни страницы «Тепловые насосы», хотя товар, который под этим запросом
ищут, у нас в каталоге уже есть.

Тепловой насос «воздух-воздух» — это не отдельный тип оборудования, а маркетинговый
ярлык на инверторной сплит-системе с низкотемпературным обогревом. Поставщики его почти
не проставляют: характеристика «Тепловой насос» приходит от Бриза у 796 товаров, но
значение «да» стоит всего у 5. Конкуренты (например, Лотос Климат) просто сложили своё
оборудование в раздел с таким названием и забрали поисковый трафик.

## 2. Факты разведки (2026-08-28, живые API по нашим ключам)

Проверено обращением к API поставщиков с прод-сервера.

### 2.1 Паспортных тепловых насосов почти нет

| Поставщик | Тепловые насосы в фиде | В наличии в Крыму |
|---|---|---|
| Русклимат | 8 категорий, товары только в двух: «воздух-воздух» (22 поз.) и «On/Off для бассейна» (1 поз.) | 2 |
| Бриз | нет ни одной из 90 категорий | — |
| Daichi | нет такой группы среди 22 | — |
| JAC | нет среди 4 разделов бланка заказа | — |

Категории «Тепловые насосы воздух-вода. Моноблоки» и «...Сплит-системы» у Русклимата
в дереве есть, но товаров в них ноль — по нашему договору не отгружаются.

У Бриза на сайте (breez.ru/services) тепловые насосы воздух-вода в линейке заявлены —
значит наш ключ выдан на ограниченный сегмент каталога. Запрос на расширение доступа
менеджеру Бриза стоит отправить, но проект от этого не зависит.

### 2.2 Зато признак низкотемпературного обогрева есть у всех троих

Характеристика приходит под тремя разными названиями:

| Поставщик | Название характеристики | Пример значения |
|---|---|---|
| Бриз | Рабочие температурные границы наружного воздуха (нагрев) | `-20 ~ +24` |
| Daichi | Диапазон рабочих температур, нагрев, °C | `-25~30` |
| Русклимат | Мин. рабочая температура воздуха для внешнего блока | `-15` |

Минимальная температура распознаётся у **2128 товаров** в текущей базе:

| Порог обогрева | Всего в каталоге | В наличии в Крыму | По поставщикам (Крым) |
|---|---|---|---|
| до −15 °C | 1321 | 175 | Бриз 112, Daichi 34, Русклимат 29 |
| **до −20 °C** | **428** | **42** | Бриз 37, Русклимат 4, Daichi 1 |
| до −25 °C | 134 | 18 | Бриз 14, Русклимат 3, Daichi 1 |

Порог −20 °C выбран владельцем: это честная граница (машина действительно греет
в крымскую зиму), при этом витрина наполнена. Внутри вкладки — фасета для сужения
до −25 и −30.

Примеры позиций, которые попадут во вкладку: FUNAI KAGAMI / EMPEROR / KADZOKU /
SHOGUN, Hisense EXPERT PRO 2.0 и VISION PRO 2.0, ROYAL CLIMA FELICITA и RENAISSANCE,
Kentatsu Otari.

## 3. Ключевое архитектурное ограничение

`Product.category` — ForeignKey: товар лежит ровно в одной категории. Если сделать
«Тепловые насосы» узлом дерева, инверторы придётся вынуть из «Бытовых сплит-систем»,
и покупатель обычного настенного FUNAI KAGAMI его там не найдёт.

Поэтому вводятся **две разные механики**, и их нельзя путать:

- **Подборка** — правило поверх каталога со своим адресом, заголовком и SEO-текстом.
  Товар остаётся в своей категории и одновременно виден в подборке. «Тепловые насосы»,
  а позже «Инверторные», «С Wi-Fi», «Для дачи» — это подборки.
- **Категория** — реальный узел дерева для товаров, которых в каталоге ещё нет:
  обогреватели, осушители, рекуператоры, водонагреватели, котлы. Это следующие этапы.

## 4. Модель данных

### 4.1 Два поля на `Product`

```python
heating_min_temp = models.SmallIntegerField(
    null=True, blank=True, db_index=True,
    help_text='Мин. температура наружного воздуха на обогреве, °C. Считается один раз '
              'при синке из tech_values (три разных названия у поставщиков) командой '
              'backfill_heating — не парсится строкой на каждый запрос.',
)
is_heat_pump = models.BooleanField(
    default=False, db_index=True,
    help_text='Поставщик сам назвал товар тепловым насосом: категория Rusklimat '
              '«Тепловые насосы...» или характеристика Бриза «Тепловой насос: да».',
)
```

Оба поля заполняются **при синке**, а не вычисляются на лету. Обоснование — то же,
что для `Product.kind` (см. `apps/catalog/classify.py`): значения характеристик хранятся
строками, разбор их регуляркой на каждый запрос каталога даёт полный скан таблицы,
и легко забыть применить фильтр в одном из мест (views / sitemap / quiz).

### 4.2 Парсер температуры

Новый модуль `apps/catalog/heating.py`, чистые функции без БД и сети:

```python
HEATING_SPEC_TITLES = (
    'Рабочие температурные границы наружного воздуха (нагрев)',   # Бриз
    'Диапазон рабочих температур, нагрев, °C',                     # Daichi
    'Мин. рабочая температура воздуха для внешнего блока',         # Rusklimat
)

def parse_min_heating_temp(value):
    """'-20 ~ +24' / '-25~30' / '-15' / '−20 ~ +24' -> -20 / -25 / -15."""
```

Требования к парсеру:

- берёт **первое отрицательное** число в строке — это нижняя граница;
- понимает минус ASCII `-`, юникодный `−` и тире `–`, разделители `~`, `-`, `—`;
- значения без отрицательного числа (`+17 ~ +30`) → `None`, товар в подборку не попадает;
- ничего не бросает на мусоре — возвращает `None`.

`min_heating_temp_for(product)` выбирает минимальное значение среди всех подходящих
характеристик товара (у товара может быть две записи от разных источников).

### 4.3 Заполнение

- **При синке:** `apps/sync/tasks.py` (Бриз), `apps/sync/rusklimat_rest.py`,
  `apps/sync/daichi_catalog.py` — после записи `ProductTech` проставляют оба поля.
- **Разово для существующих:** management-команда `backfill_heating` по образцу
  `backfill_product_kind` и `compute_btu`. В базе сейчас ~4500 активных товаров,
  у 2128 температура распознаётся.

## 5. Подборки и витрина

### 5.1 Реестр подборок

`apps/catalog/collections.py` — список подборок в коде (не модель в БД: сейчас нужна
одна, админка для них — преждевременное усложнение):

```python
COLLECTIONS = {
    'heat-pumps': Collection(
        slug='heat-pumps',
        title='Тепловые насосы',
        h1='Тепловые насосы воздух-воздух в Крыму',
        seo_text='...',
        rule=Q(kind=Product.KIND_SPLIT_SYSTEM) & (
            Q(is_heat_pump=True) | Q(heating_min_temp__lte=-20)
        ),
    ),
}
```

Добавление следующей подборки («Инверторные», «С Wi-Fi») — одна запись в словаре,
без нового кода и без миграций.

`seo_text` — продающий текст под листингом (2–3 абзаца про то, что сплит-система
с обогревом до −20 °C заменяет отопление в межсезонье и работает эффективнее
электрокотла). Пишется при реализации и согласуется с владельцем.

### 5.2 Страница

- URL `/catalog/<slug>/` → `collection_view`, 404 на неизвестный slug.
- View собирает тот же `base_qs`, что и `catalog()`, накладывает `rule` подборки
  и рендерит **существующий** шаблон каталога — фильтры, фасеты, сортировка, пагинация,
  htmx-обновление работают без изменений.
- Свои `h1`, `title`, `description` и SEO-текст под листингом.
- Подборка попадает в `sitemap.py`.

### 5.3 Показ «под заказ»

Каталог по умолчанию показывает только крымский склад (`with_order=1` расширяет).
Для подборки правило то же: 42 позиции в наличии по умолчанию, 428 — по ссылке
«показать под заказ». Паспортные теплонасосы Русклимата крымского остатка не имеют
и видны только под заказ, с существующей плашкой карточки.

### 5.4 Фасета «Работает на обогрев до»

Добавляется в `apps/catalog/filters.py` как обычная фасета по `heating_min_temp`:
чекбоксы −20 / −25 / −30 (`heating_min_temp__lte`). Доступна и в общем каталоге,
не только в подборке.

### 5.5 Навигация

Пункт «Тепловые насосы» в левом дереве каталога — под списком категорий, отдельной
группой «Подборки», чтобы не смешивать с категориями. Плюс пункт в шапке.

## 6. Синк Русклимата: впустить паспортные тепловые насосы

`_AC_CATEGORY_RE` в `apps/sync/rusklimat_rest.py:55` не пропускает «Тепловые насосы
воздух-воздух» (22 товара). Изменения:

- в regex добавляется `теплов\w*\s+насос`;
- `_master_category_for` раскладывает их в «Бытовые сплит-системы» (это и есть сплиты);
- при синке им проставляется `is_heat_pump=True` — по названию категории поставщика.

Результат: +23 позиции, все под заказ.

`_AC_EXCLUDE_RE` не трогаем — он отсекает аксессуары и запчасти, это по-прежнему верно.

## 8. Тестирование

Тесты без БД и сети (быстрые, по стилю проекта):

- `parse_min_heating_temp` — таблица случаев: `-20 ~ +24`, `-25~30`, `-15`,
  `−20 ~ +24` (юникодный минус), `+17 ~ +30` → None, `''` → None, мусор → None.
- `min_heating_temp_for` — выбор минимума из нескольких характеристик.

Тесты с БД:

- правило подборки: товар с `heating_min_temp=-20` попадает, с `-15` не попадает,
  аксессуар с `-25` не попадает (отсекается `kind`);
- `is_heat_pump=True` попадает независимо от температуры;
- страница подборки отвечает 200 и показывает ожидаемое число товаров;
- неизвестный slug → 404.

Проверка на проде после деплоя: число товаров в подборке равно 42 (в наличии)
и 428 (с «под заказ») — цифры зафиксированы разведкой 2026-08-28 и могут смениться
после суточного синка, порядок величины должен совпасть.

## 9. Риски

- **Характеристики приходят не всем товарам.** У Русклимата из 2823 активных товаров
  характеристики есть у 915 — часть инверторов в подборку не попадёт. Не блокер:
  подборка наполняется, покрытие вырастет, когда доделаем синк характеристик Русклимата.
- **Поставщик меняет название характеристики.** Тогда часть товаров тихо выпадет.
  Смягчение: `backfill_heating` логирует, сколько товаров получили значение;
  резкое падение видно в логах.
- **Маркетинговая претензия «это не настоящий тепловой насос».** Порог −20 °C и явная
  формулировка на странице («сплит-системы с низкотемпературным обогревом до −20 °C»)
  снимают вопрос; ярлык «воздух-воздух» в h1 — честный.
